# Vivado Power & Voltage Analysis: Deep Dive into UG907

## 1. Executive Summary of UG907

AMD Vivado provides dedicated power estimation and optimization capabilities documented in **UG907: Vivado Design Suite User Guide: Power Analysis and Optimization**.

In modern semiconductor devices (CMOS FPGAs such as 7-Series, UltraScale, and UltraScale+), power consumption directly limits device reliability, thermal envelope, package selection, and power supply design. Vivado evaluates power across two operational domains:
1. **Static Power (Quiescent Power)**: Consumed when the device is powered on, configured, but no clocks are running. Driven by sub-threshold leakage currents and gate oxide leakage.
2. **Dynamic Power (Active Power)**: Consumed by internal transistor switching and charging/discharging parasitic interconnect and pin capacitances as signals toggle.

---

## 2. Mathematical Foundations of Dynamic Power

The physical equation governing dynamic power dissipation in digital CMOS logic is:

$$P_{\text{dynamic}} = \sum_{i \in \text{all nets}} \left( \frac{1}{2} \cdot C_i \cdot V_{i}^2 \cdot f_{\text{clk}} \cdot \alpha_i \right) + \sum_{g \in \text{cells}} P_{\text{internal}, g}$$

Where:
- **$C_i$ (Capacitance)**: The total lump capacitance on net $i$, comprising:
  - Output driver pin capacitance ($C_{\text{out}}$).
  - Parasitic interconnect routing wire capacitance ($C_{\text{wire}} = c_{\text{unit}} \cdot L$).
  - Fan-out input gate pin capacitances ($\sum C_{\text{in}, j}$).
- **$V_i$ (Operational Voltage)**: The supply rail voltage connected to the driver ($V_{\text{ccint}} \approx 0.72\text{V} - 1.0\text{V}$, $V_{\text{ccaux}} \approx 1.8\text{V}$, $V_{\text{cco}} \approx 1.2\text{V} - 3.3\text{V}$).
- **$f_{\text{clk}}$ (Reference Clock Frequency)**: The fundamental clock frequency associated with the clock domain driving the net.
- **$\alpha_i$ (Switching Activity / Toggle Rate)**: The average number of logic transitions ($0 \to 1$ or $1 \to 0$) per clock cycle. For instance:
  - A clock net toggling twice per cycle (rising + falling) has $\alpha = 2.0$ (or 200%).
  - A data signal transitioning once every 4 clock cycles has $\alpha = 0.25$ (25%).
- **$P_{\text{internal}, g}$ (Cell Internal Power)**: Short-circuit power dissipated inside logic cells (e.g. LUTs, DSP slices, BRAMs) when PMOS and NMOS transistors simultaneously conduct momentarily during switching.

## 3. Vivado Switching Activity Ingestion: Vector-Based vs. Vectorless

Vivado's `report_power` tool supports two distinct methodologies to ascertain $\alpha_i$ and static probability $P(1)$ for every net in the design:

```
                  +----------------------------------------------+
                  |           HDL Testbench Simulation           |
                  +----------------------------------------------+
                                         |
                        +----------------+----------------+
                        |                                 |
                        v                                 v
         +-----------------------------+   +-----------------------------+
         | Vector-Based Flow (SAIF)    |   | Vectorless Estimation Engine|
         | - Captures exact toggles    |   | - Used when no testbench    |
         | - Generated by xsim/xelab   |   |   is available              |
         | - High accuracy (+/- 5%)    |   | - Propagates default rates  |
         +--------------+--------------+   | - Typical accuracy (+/- 30%)|
                        |                  +--------------+--------------+
                        +----------------+----------------+
                                         |
                                         v
                  +----------------------------------------------+
                  |         Vivado report_power Engine           |
                  |  - Computes per-net capacitive load          |
                  |  - Applies Vdd rail potentials               |
                  |  - Integrates dynamic and static power       |
                  |  - Generates thermal margin & power budgets  |
                  +----------------------------------------------+
```

### 3.1. Vector-Based Flow (SAIF & VCD)
- **SAIF (Switching Activity Interchange Format)**: An industry-standard format (IEEE 1801 / A-SAIF) that records:
  - `T0`: Total time the signal was at logic `0`.
  - `T1`: Total time the signal was at logic `1`.
  - `TX`: Total time the signal was in an unknown state `X`.
  - `TC`: Total transition count (toggle count).
- In `xsim`, dumping SAIF is performed via Tcl:
  ```tcl
  open_saif "switching.saif"
  log_saif [get_objects -r /tb_top/u_dut/*]
  run 100us
  close_saif
  ```
- In Vivado synthesis/implementation:
  ```tcl
  read_saif "switching.saif"
  report_power -file power_report.txt
  ```

### 3.2. Vectorless Estimation Flow
If no simulation snapshot is available, Vivado uses a heuristic probabilistic propagation model:
- Primary inputs without constraints default to a toggle rate $\alpha = 0.125$ (12.5%) and static probability $P(1) = 0.5$.
- Clocks default to $\alpha = 2.0$.
- Logic gate propagation rules:
  - **AND Gate** ($Y = A \cdot B$):
    $$P_Y(1) = P_A(1) \cdot P_B(1)$$
    $$\alpha_Y = P_A(1)^2 \cdot \alpha_B + P_B(1)^2 \cdot \alpha_A$$
  - **OR Gate** ($Y = A + B$):
    $$P_Y(1) = 1 - (1 - P_A(1)) \cdot (1 - P_B(1))$$
  - **XOR Gate** ($Y = A \oplus B$):
    $$P_Y(1) = P_A(1)(1 - P_B(1)) + P_B(1)(1 - P_A(1))$$

## 4. Voltage Rails & Rail Current Estimation

Vivado groups power dissipation across physical power supply rails:
1. **$V_{\text{CCINT}}$ (Internal Core Voltage)**: Powers CLBs, LUTs, internal flip-flops, DSPs, routing interconnect. (e.g. 0.85V for Artix-7, 0.72V for UltraScale+).
2. **$V_{\text{CCBRAM}}$ (Block RAM Voltage)**: Powers dedicated dual-port RAM blocks.
3. **$V_{\text{CCAUX}}$ (Auxiliary Voltage)**: Powers clock buffers, JTAG, PLLs, DCMs (typically 1.8V).
4. **$V_{\text{CCO}}$ (I/O Bank Voltages)**: Selectable per bank (1.2V, 1.5V, 1.8V, 2.5V, 3.3V) depending on I/O standards (LVCMOS, LVDS, SSTL).

Current on each rail is derived directly:
$$I_{\text{rail}} = \frac{P_{\text{rail}}}{V_{\text{rail}}}$$

## 5. Architectural Critique & Betterado Telemetry Architecture

### Vivado's Flaws:
- **Offline & Disconnected**: In Vivado, power analysis is an offline post-processing step. You must run the simulation, close `xsim`, generate a SAIF file, open the implemented netlist in Vivado, and run `report_power`. There is **zero real-time feedback** during simulation.
- **No Temporal / Instantaneous Energy Graphing**: Vivado only gives an aggregate average power over the entire simulation window. It cannot graph dynamic current spikes or instantaneous energy surges across a 10ns clock cycle.

### Betterado's Real-Time Engine:
- **Physics-Integrated Sim Kernel**: Every signal update in Betterado's JIT simulation loop tracks switching activity and instantaneous energy dissipation:
  $$E_{\text{event}} = \frac{1}{2} C_{\text{net}} V_{\text{net}}^2$$
- **Live Streamed Telemetry**: Ring-buffer streaming emits instantaneous power and cumulative energy samples directly to the Tauri/React GUI at 60 FPS.
- **Interactive Voltage / Energy Graphs**: Users see dynamic current spikes synchronized with the digital waveform viewer, pinpointing exactly which clock edge or instruction causes a power surge.
